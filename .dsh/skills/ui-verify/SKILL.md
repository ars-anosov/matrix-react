# Проверка UI в браузере

Сначала сформулировать **одно проверяемое утверждение**. Для текстов, пропсов и разметки без
зависимости от каскада достаточно чтения diff и при необходимости `npx biome check src/` /
`npm run build`; браузер нужен только для рантайма, визуального результата и консоли/сети.

## Порядок

1. Проверить, отвечает ли `http://localhost:3000/` **этим проектом**. Если нет — запустить
   `npm run dev` отдельным managed background job и дождаться `curl -sf http://localhost:3000/`
   (не ставить `npm run dev` и `curl` подряд в одном скрипте: сервер не завершится). Vite может
   занять следующий свободный порт — брать фактический URL из лога. При смене порта учесть:
   dev-дефолт `uriAdAuth` в `index.html` указывает на `localhost:3000/user/ad`.
2. В рабочем каталоге проекта выполнить **весь сценарий одним вызовом `bash`**: демон CLI не
   переживает отдельные вызовы. Браузер запускать только обёрткой `.dsh/bin/browser` (она
   настраивает записываемый HOME); без `--headed`. Выбрать действия под утверждение:

   ```bash
   set -e
   trap '.dsh/bin/browser close >/dev/null 2>&1 || true' EXIT
   .dsh/bin/browser open http://localhost:3000/
   .dsh/bin/browser snapshot --depth=4
   .dsh/bin/browser console error
   .dsh/bin/browser requests
   .dsh/bin/browser screenshot --filename=.playwright/cache/output/ui-check.png
   ```

   Для кликов брать актуальные `ref` из снапшота; после клика обновлять снапшот — `ref` меняются.
   Состояния и computed styles смотреть через `run-code`, не по картинке. `find` ищет текстовые
   узлы, не accessible names. Для параллельных прогонов в одном проекте задавать разные
   `PLAYWRIGHT_CLI_SESSION`.
3. Проверить лишь затронутое. Mock API — `mock/vite-mock-api.js`, ключи хранилища —
   `constants/storage.js`; у открытого MUI drawer остальное приложение `aria-hidden` — сначала
   закрыть его, затем искать элементы. Ошибки — `console error`, запросы — `requests`
   (по умолчанию скрывает статические файлы; для них нужен `requests --static`).
4. В отчёте указать URL, шаги, наблюдение и ошибки. Скриншот для визуального утверждения
   посмотреть через `read_image`/доступный инструмент зрения; если инструмент недоступен,
   не заявлять о визуальном осмотре. Человеку открыть URL через `win_open_url`, только если он
   должен увидеть результат. Остановить **только свой** dev-job, удалить автофайлы текущего
   прогона из `.playwright/cache/output/` (`page-*`, `console-*`); именованный скриншот можно
   оставить. Кэш игнорируется Git.

Если браузер не открылся, проверить `.playwright/cli.config.json` (без него CLI может выбрать
несуществующий Chrome), наличие `playwright-cli` и Chromium, затем библиотеки из ошибки запуска.
Обёртка сохраняет путь к общему кэшу браузеров **до** замены HOME; не заменять её прямым вызовом
CLI. `Browser 'default' is not open` обычно означает, что сценарий разбили на несколько вызовов
`bash`. Баннер о новой версии CLI сам по себе не ошибка.
